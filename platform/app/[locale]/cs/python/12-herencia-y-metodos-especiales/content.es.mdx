# Herencia y métodos especiales

<Accroche>« Un jefe ES UN enemigo — con más vida. La herencia deja que una clase reutilice a otra y añada lo suyo. »</Accroche>

La **herencia** deja que una clase reutilice a otra. Y los **métodos especiales** (los de nombre
`__algo__`, llamados *dunder*) integran tus objetos con el propio Python: que se impriman bonito, se
comparen, se sumen… Es la base para modelar toda una jerarquía de enemigos.

## Heredar

Una subclase pone entre paréntesis la clase de la que hereda. Recibe todos sus atributos y métodos, y
puede **sustituir** (sobrescribir) los que quiera:

```python
class Enemigo:
    def __init__(self, nombre):
        self.nombre = nombre
    def atacar(self):
        return "..."

class Slime(Enemigo):        # un Slime ES UN Enemigo
    def atacar(self):        # sobrescribe atacar
        return "embiste"

gloopy = Slime("Gloopy")
print(gloopy.nombre)         # Gloopy   (heredado de Enemigo)
print(gloopy.atacar())       # embiste
```

## `super()` — reutilizar el constructor del padre

Cuando una subclase quiere ampliar el `__init__` del padre en vez de reescribirlo, llama a `super()`.
Un jefe es un enemigo, pero con mucha más vida:

```python
class Enemigo:
    def __init__(self, hp):
        self.hp = hp

class Jefe(Enemigo):
    def __init__(self):
        super().__init__(500)    # llama al __init__ de Enemigo con 500 de hp
        self.tipo = "jefe"

b = Jefe()
print(b.hp)   # 500
```

{/* sol:
class Enemigo:
    def __init__(self, hp):
        self.hp = hp

class Jefe(Enemigo):
    def __init__(self):
        super().__init__(500)

print(Jefe().hp)
*/}
<PyExercise
  task="Usa super() para que un Jefe se cree con 500 de hp. Imprime su hp."
  starter={`class Enemigo:
    def __init__(self, hp):
        self.hp = hp

class Jefe(Enemigo):
    def __init__(self):
        # llama al constructor del padre con 500
        pass

print(Jefe().hp)`}
  expected_output="500"
  hint={`super().__init__(500)`}
/>

## `__str__` — cómo se imprime tu objeto

Sin `__str__`, imprimir un objeto muestra algo feo como `<__main__.Punto object at 0x...>`. Defínelo
para controlar su aspecto — por ejemplo, la posición de un sprite:

```python
class Punto:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    def __str__(self):
        return f"({self.x}, {self.y})"

print(Punto(3, 4))   # (3, 4)
```

{/* sol:
class Punto:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    def __str__(self):
        return f"({self.x}, {self.y})"

print(Punto(3, 4))
*/}

## Polimorfismo

Objetos de clases distintas que comparten un método pueden tratarse **igual**. Es la magia que hace
el código flexible — un bucle que ataca con cualquier arma:

```python
class Espada:
    def atacar(self): return "corta"
class Arco:
    def atacar(self): return "dispara"

for arma in [Espada(), Arco()]:
    print(arma.atacar())   # corta / dispara
```

{/* sol:
class Espada:
    def atacar(self):
        return "corta"
class Arco:
    def atacar(self):
        return "dispara"

for arma in [Espada(), Arco()]:
    print(arma.atacar())
*/}

<Pitfall>
`__str__` es para personas (una descripción bonita); `__repr__` es para desarrolladores (una versión
técnica, ideal en depuración). Si solo defines uno, que sea `__repr__`: Python lo usa como respaldo.
</Pitfall>

## Mini-ejercicios

<Collapsible title="1. ¿Qué método permite comparar dos objetos con == ?">

`__eq__(self, otro)`. Por defecto, dos objetos solo son iguales si son *el mismo*; con `__eq__`
defines tú qué significa que sean iguales (por ejemplo, dos posiciones con los mismos `x` e `y`).

<Collapsible title="2. Una clase Jefe que herede de Enemigo con super().">

```python
class Enemigo:
    def __init__(self, nombre, hp):
        self.nombre, self.hp = nombre, hp

class Jefe(Enemigo):
    def __init__(self, nombre):
        super().__init__(nombre, 500)

print(Jefe("Bowser").hp)   # 500
```
