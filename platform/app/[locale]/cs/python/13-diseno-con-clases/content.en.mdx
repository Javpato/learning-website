# Designing with Classes

<Accroche>« Knowing how to write classes is easy. Knowing how to combine them is designing a game. »</Accroche>

You already know how to create classes and inherit. This chapter is about **designing well**: when to
compose instead of inherit, how to compute attributes with properties, and how to write less with
`dataclasses`.

## Composition: "has a"

Inheritance says "**is a**" (`Slime` is an `Enemigo`). **Composition** says "**has a**": an object is
built from other objects. A hero *has a* weapon. It's usually more flexible than inheritance.

```python
class Arma:
    def usar(self):
        return "slashes"

class Heroe:
    def __init__(self):
        self.arma = Arma()        # a Heroe HAS AN Arma
    def atacar(self):
        return self.arma.usar()

print(Heroe().atacar())   # slashes
```

## `@property` — computed attributes

A `@property` is a method used **as if it were an attribute** (no parentheses). Ideal for derived
values, like critical damage (double the strength):

```python
class Heroe:
    def __init__(self, fuerza):
        self.fuerza = fuerza

    @property
    def critico(self):
        return self.fuerza * 2

h = Heroe(5)
print(h.critico)   # 10   (no parentheses!)
```

## `dataclasses` — data classes without ceremony

When a class is mostly **data** (a sprite's position, an item's sheet), `@dataclass` writes the
`__init__`, the `__repr__` and the `__eq__` for free:

```python
from dataclasses import dataclass

@dataclass
class Punto:
    x: int
    y: int

p = Punto(3, 4)
print(p)          # Punto(x=3, y=4)   (automatic __repr__!)
print(p == Punto(3, 4))   # True      (automatic __eq__)
```

<Pitfall>
Don't overuse inheritance. Before building a five-level enemy hierarchy, ask yourself whether it's
clearer to **compose** small objects (an enemy that *has a* weapon and *has a* movement pattern). Rule
of thumb: *composition over inheritance*.
</Pitfall>

<Collapsible title="2. A property with validation on assignment (setter).">

```python
class Personaje:
    def __init__(self, vida):
        self._vida = vida
    @property
    def vida(self):
        return self._vida
    @vida.setter
    def vida(self, valor):
        self._vida = max(0, valor)   # health never drops below 0
```
