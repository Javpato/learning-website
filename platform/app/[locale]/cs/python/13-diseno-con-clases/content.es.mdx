# Diseño con clases

<Accroche>« Saber escribir clases es fácil. Saber cómo combinarlas es diseñar un juego. »</Accroche>

Ya sabes crear clases y heredar. Este capítulo trata de **diseñar bien**: cuándo componer en vez de
heredar, cómo calcular atributos con propiedades y cómo escribir menos con `dataclasses`.

## Composición: "tiene un"

La herencia dice "**es un**" (`Slime` es un `Enemigo`). La **composición** dice "**tiene un**": un
objeto se construye con otros objetos. Un héroe *tiene un* arma. Suele ser más flexible que la herencia.

```python
class Arma:
    def usar(self):
        return "corta"

class Heroe:
    def __init__(self):
        self.arma = Arma()        # un Heroe TIENE UN Arma
    def atacar(self):
        return self.arma.usar()

print(Heroe().atacar())   # corta
```

## `@property` — atributos calculados

Un `@property` es un método que se usa **como si fuera un atributo** (sin paréntesis). Ideal para
valores derivados, como el daño crítico (el doble de la fuerza):

```python
class Heroe:
    def __init__(self, fuerza):
        self.fuerza = fuerza

    @property
    def critico(self):
        return self.fuerza * 2

h = Heroe(5)
print(h.critico)   # 10   (¡sin paréntesis!)
```

{/* sol:
class Heroe:
    def __init__(self, fuerza):
        self.fuerza = fuerza
    @property
    def critico(self):
        return self.fuerza * 2

print(Heroe(5).critico)
*/}

## `dataclasses` — clases de datos sin ceremonia

Cuando una clase es sobre todo **datos** (la posición de un sprite, la ficha de un objeto),
`@dataclass` te escribe el `__init__`, el `__repr__` y el `__eq__` gratis:

```python
from dataclasses import dataclass

@dataclass
class Punto:
    x: int
    y: int

p = Punto(3, 4)
print(p)          # Punto(x=3, y=4)   (¡__repr__ automático!)
print(p == Punto(3, 4))   # True      (__eq__ automático)
```

{/* sol:
from dataclasses import dataclass

@dataclass
class Punto:
    x: int
    y: int

print(Punto(3, 4))
*/}

<Pitfall>
No abuses de la herencia. Antes de crear una jerarquía de cinco niveles de enemigos, pregúntate si no
es más claro **componer** objetos pequeños (un enemigo que *tiene un* arma y *tiene un* patrón de
movimiento). Regla práctica: *composición sobre herencia*.
</Pitfall>

<Collapsible title="1. ¿Qué te da gratis un @dataclass?">

El constructor (`__init__`), una representación legible (`__repr__`) y la comparación por valor
(`__eq__`). Escribes solo los campos y sus tipos.

</Collapsible>

<Collapsible title="2. Una property con validación al asignar (setter).">

```python
class Personaje:
    def __init__(self, vida):
        self._vida = vida
    @property
    def vida(self):
        return self._vida
    @vida.setter
    def vida(self, valor):
        self._vida = max(0, valor)   # la vida nunca baja de 0
```
