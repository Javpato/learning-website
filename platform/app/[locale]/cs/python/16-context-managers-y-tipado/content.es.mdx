# Context managers y tipado

<Accroche>« Empieza y termina un combate sin olvidos, y documenta tus tipos para que el editor te ayude. »</Accroche>

Dos herramientas de código profesional: los **context managers** (el `with` que ya usaste con
archivos) y las **anotaciones de tipo**, que hacen tu código más claro y permiten que las
herramientas detecten errores antes de ejecutarlo.

## El `with`, por dentro

`with` garantiza que algo se **cierre** pase lo que pase (aunque haya un error). Por eso abrimos
archivos así — y por eso es perfecto para enmarcar un combate: empieza al entrar y termina al salir.
Puedes crear los tuyos con `contextlib`:

```python
from contextlib import contextmanager

@contextmanager
def combate(enemigo):
    print(f"¡Empieza el combate contra {enemigo}!")   # al entrar
    yield                                             # aquí va el cuerpo del with
    print("Combate terminado")                        # al salir

with combate("Slime"):
    print("atacas")
# ¡Empieza el combate contra Slime!
# atacas
# Combate terminado
```

## Versión con clase: `__enter__` / `__exit__`

Un objeto es un context manager si define esos dos métodos. Ideal para una partida que **se guarda
sola** al salir:

```python
class Partida:
    def __enter__(self):
        print("cargar")
        return self
    def __exit__(self, *args):
        print("guardar")

with Partida():
    print("jugar")
# cargar / jugar / guardar
```

## Anotaciones de tipo

Puedes indicar de qué **tipo** son los parámetros y el resultado. Python **no** lo obliga en ejecución,
pero tu editor y herramientas como `mypy` lo usan para avisarte de errores:

```python
def crear_enemigo(nombre: str) -> str:
    return "Enemigo: " + nombre

vida: int = 100
enemigos: list[str] = ["Slime", "Goomba"]
```

<Pitfall>
Las anotaciones de tipo son **documentación que no se comprueba sola** en ejecución: `vida: int = "x"`
no da error al correr el programa. Sirven para el editor y para `mypy`. No las confundas con una
validación real (para eso, un `if` o un `raise`).
</Pitfall>

## Mini-ejercicios

<Collapsible title="1. ¿Qué garantiza el with al abrir un archivo de guardado?">

Que el archivo se **cierre** al terminar el bloque, incluso si dentro salta una excepción. Es el
mismo mecanismo `__enter__`/`__exit__` que has visto aquí.

</Collapsible>

<Collapsible title="2. ¿Cómo anotar una función que puede devolver None?">

Con `Optional` (o `| None`):

```python
from typing import Optional
def buscar_enemigo(id: int) -> Optional[str]:
    ...
# o, en Python moderno:  def buscar_enemigo(id: int) -> str | None:
```

</Collapsible>
