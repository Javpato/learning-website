# Clases y objetos

<Accroche>« Una clase es un molde. Cada objeto que creas con él es una pieza con vida propia — como cada enemigo que aparece en pantalla. »</Accroche>

Hasta ahora tus datos y tus funciones iban por separado. La **programación orientada a objetos** los
junta: una **clase** describe *qué datos* tiene algo y *qué puede hacer*. Cada ejemplar concreto es un
**objeto** (o *instancia*). Es la forma natural de modelar personajes, enemigos y objetos de un juego.

## Tu primera clase

```python
class Personaje:
    def __init__(self, nombre):
        self.nombre = nombre       # un atributo (dato del objeto)

    def atacar(self):              # un método (algo que el objeto hace)
        return self.nombre + " ataca"

heroe = Personaje("Link")          # creamos un objeto
print(heroe.nombre)                # Link
print(heroe.atacar())              # Link ataca
```

- `__init__` es el **constructor**: se ejecuta al crear el objeto y prepara sus atributos.
- `self` es **el propio objeto**. Siempre es el primer parámetro de los métodos, y con él accedes a
  sus atributos (`self.nombre`).

## Estado que cambia

Los objetos **recuerdan** su estado entre llamadas a sus métodos — por ejemplo, un contador de combo:

```python
class Combo:
    def __init__(self):
        self.golpes = 0

    def golpear(self):
        self.golpes += 1

c = Combo()
c.golpear()
c.golpear()
print(c.golpes)   # 2
```

{/* sol:
class Combo:
    def __init__(self):
        self.golpes = 0
    def golpear(self):
        self.golpes += 1

c = Combo()
c.golpear()
c.golpear()
print(c.golpes)
*/}
<PyExercise
  task="Crea un Combo, golpea dos veces e imprime cuántos golpes lleva."
  starter={`class Combo:

        self.golpes = 0

        pass

print(c.golpes)`}
  expected_output="2"
  hint={`self.golpes += 1 dentro de golpear.`}
/>

<Pitfall>
Olvidar `self` es el error clásico. Dentro de un método, `self.golpes` es el atributo del objeto;
`golpes` a secas sería una variable local que se pierde. Y todo método lleva `self` como primer
parámetro, aunque al llamarlo no lo pases (`c.golpear()`, no `c.golpear(c)`).
</Pitfall>

## Varios objetos, moldes independientes

Cada objeto tiene **sus propios** atributos. Dos ataques distintos, cada uno con su daño:

```python
class Ataque:
    def __init__(self, daño, golpes):
        self.daño = daño
        self.golpes = golpes

    def total(self):
        return self.daño * self.golpes

espada = Ataque(4, 3)
patada = Ataque(10, 2)
print(espada.total(), patada.total())   # 12 20
```

{/* sol:

## Mini-ejercicios

<Collapsible title="1. ¿Qué diferencia hay entre una clase y un objeto?">

La **clase** es el molde (la receta): `Personaje`. El **objeto** es una pieza concreta creada con ese
molde: `heroe = Personaje("Link")`. De una clase puedes crear muchos objetos independientes (todos los
enemigos de una oleada).

</Collapsible>

<Collapsible title="2. Una clase Heroe con curar y recibir_daño.">

```python
class Heroe:
    def __init__(self, hp=100):
        self.hp = hp
    def curar(self, cantidad):
        self.hp += cantidad
    def recibir_daño(self, cantidad):
        self.hp -= cantidad

h = Heroe(100)
h.curar(50)
h.recibir_daño(30)
print(h.hp)   # 120
```

</Collapsible>
