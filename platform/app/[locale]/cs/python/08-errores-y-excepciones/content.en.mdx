# Errors and Exceptions

<Accroche>« Robust games don't avoid errors: they expect them and handle them gracefully — the player typing anything shouldn't crash the game. »</Accroche>

Until now, when something went wrong, the program **broke** with a red message. In this chapter you
learn to **catch** those errors and react without everything falling over — essential the moment a
player types into your menu.

## What an exception is

When Python can't continue, it raises an **exception**. Each type has a name:

```python
int("espada")      # ValueError: not a number
[1, 2][5]          # IndexError: index out of range
100 / 0            # ZeroDivisionError
{"hp": 30}["mp"]   # KeyError: the key doesn't exist
```

## `try` / `except`

Wrap the code that *might* fail with `try`, and say what to do if it fails in `except`. Perfect for
reading the option the player types:

```python
try:
    opcion = int(input("Choose character (1-3): "))
    print("You chose", opcion)
except ValueError:
    print("That's not a valid number.")
```

## Catching the right type

Catch the **specific** type you expect. That way you don't hide errors you didn't foresee. For example,
when splitting a spell's damage among the enemies, watch out if there are none:

```python
def repartir(total, enemigos):
    try:
        return total / enemigos
    except ZeroDivisionError:
        return "no enemies"

print(repartir(30, 3))   # 10.0
print(repartir(30, 0))   # no enemies
```

## `else` and `finally`

- `else` runs if there was **no** error.
- `finally` runs **always** (handy for closing resources, like the save file).

```python
try:
    x = int("42")
except ValueError:
    print("error")
else:
    print("all good:", x)   # this runs
finally:
    print("done")
```

## Raising your own errors: `raise`

When *you* detect an invalid situation, raise it with `raise`:

```python
def curar(hp, cantidad):
    if cantidad < 0:
        raise ValueError("can't heal a negative amount")
    return hp + cantidad
```

<Pitfall>
Avoid the "bare" `except:` (with no type) or `except Exception`: it catches **everything**, even
programming errors you'd want to see. Catch the specific type (`ValueError`, `KeyError`…) and let the
unexpected show.
</Pitfall>
