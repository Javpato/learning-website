# Errores y excepciones

<Accroche>« Los programas robustos no evitan los errores: los esperan y los manejan con elegancia. »</Accroche>

Hasta ahora, cuando algo iba mal, el programa se **rompía** con un mensaje rojo. En este capítulo
aprendes a **atrapar** esos errores y a reaccionar sin que todo se caiga.

## Qué es una excepción

Cuando Python no puede continuar, lanza una **excepción**. Cada tipo tiene un nombre:

```python
int("hola")     # ValueError: no es un número
[1, 2][5]       # IndexError: índice fuera de rango
10 / 0          # ZeroDivisionError
{"a": 1}["b"]   # KeyError: la clave no existe
```

## `try` / `except`

Rodea el código que *podría* fallar con `try`, y di qué hacer si falla en `except`:

```python
try:
    edad = int(input("Tu edad: "))
    print("El año que viene tendrás", edad + 1)
except ValueError:
    print("Eso no es un número válido.")
```

## Capturar el tipo correcto

Atrapa el tipo **concreto** que esperas. Así no ocultas errores que no previste:

```python
def dividir(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return "No se puede dividir entre cero"

print(dividir(10, 2))   # 5.0
print(dividir(10, 0))   # No se puede dividir entre cero
```

## `else` y `finally`

- `else` se ejecuta si **no** hubo error.
- `finally` se ejecuta **siempre** (útil para limpiar recursos).

```python
try:
    x = int("42")
except ValueError:
    print("error")
else:
    print("todo bien:", x)   # se ejecuta esto
finally:
    print("listo")
```

## Lanzar tus propios errores: `raise`

Cuando *tú* detectas una situación inválida, lánzala con `raise`:

```python
def raiz(n):
    if n < 0:
        raise ValueError("no hay raíz real de un número negativo")
    return n ** 0.5
```

<Pitfall>
Evita el `except:` "pelado" (sin tipo) o `except Exception`: atrapa **todo**, incluso errores de
programación que querrías ver. Captura el tipo específico (`ValueError`, `KeyError`…) y deja que lo
inesperado se note.
</Pitfall>
