# Errores y excepciones

<Accroche>« Los juegos robustos no evitan los errores: los esperan y los manejan con elegancia — que el jugador escriba cualquier cosa no debe cerrar el juego. »</Accroche>

Hasta ahora, cuando algo iba mal, el programa se **rompía** con un mensaje rojo. En este capítulo
aprendes a **atrapar** esos errores y a reaccionar sin que todo se caiga — imprescindible en cuanto un
jugador escribe en tu menú.

## Qué es una excepción

Cuando Python no puede continuar, lanza una **excepción**. Cada tipo tiene un nombre:

```python
int("espada")      # ValueError: no es un número
[1, 2][5]          # IndexError: índice fuera de rango
100 / 0            # ZeroDivisionError
{"hp": 30}["mp"]   # KeyError: la clave no existe
```

## `try` / `except`

Rodea el código que *podría* fallar con `try`, y di qué hacer si falla en `except`. Perfecto para leer
la opción que teclea el jugador:

```python
try:
    opcion = int(input("Elige personaje (1-3): "))
    print("Elegiste el", opcion)
except ValueError:
    print("Eso no es un número válido.")
```

## Capturar el tipo correcto

Atrapa el tipo **concreto** que esperas. Así no ocultas errores que no previste. Por ejemplo, al
repartir el daño de un hechizo entre los enemigos, cuidado si no hay ninguno:

```python
def repartir(total, enemigos):
    try:
        return total / enemigos
    except ZeroDivisionError:
        return "sin enemigos"

print(repartir(30, 3))   # 10.0
print(repartir(30, 0))   # sin enemigos
```

## `else` y `finally`

- `else` se ejecuta si **no** hubo error.
- `finally` se ejecuta **siempre** (útil para cerrar recursos, como el archivo de guardado).

```python
try:
    x = int("42")
except ValueError:
    print("error")
else:
    print("todo bien:", x)   # se ejecuta esto
finally:
    print("listo")
```

## Lanzar tus propios errores: `raise`

Cuando *tú* detectas una situación inválida, lánzala con `raise`:

```python
def curar(hp, cantidad):
    if cantidad < 0:
        raise ValueError("no se puede curar una cantidad negativa")
    return hp + cantidad
```

<Pitfall>
Evita el `except:` "pelado" (sin tipo) o `except Exception`: atrapa **todo**, incluso errores de
programación que querrías ver. Captura el tipo específico (`ValueError`, `KeyError`…) y deja que lo
inesperado se note.
</Pitfall>
