# Construye tu propia app de datos

<Accroche>« Detrás de toda app y de todo videojuego hay lo mismo: crear, leer, actualizar y borrar datos. Aprende ese esqueleto y podrás construir cualquier cosa. »</Accroche>

Una Pokédex, el inventario de un juego, una red social, una tienda: por dentro todas hacen lo mismo,
las cuatro operaciones **CRUD** (*Create, Read, Update, Delete*). Este capítulo te enseña ese patrón
con datos en memoria, para que en el **Proyecto 9** construyas tu propia **Pokédex** desde cero.

## Qué es CRUD

```text
Create  → crear un registro
Read    → leer / buscar registros
Update  → actualizar un registro
Delete  → borrar un registro
```

## El registro: un diccionario con id

Cada cosa que guardas (un Pokémon, un objeto, un usuario) es un **registro**: un diccionario con sus
campos y, muy importante, un **id** único que lo identifica.

```python
pikachu = {"id": 1, "nombre": "Pikachu", "tipo": "Eléctrico", "hp": 35}
print(pikachu["nombre"])   # Pikachu
```

## Todos los registros: una lista

La base de datos entera es una **lista** de esos diccionarios. La llamaremos `pokedex`:

```python
pokedex = [
    {"id": 1, "nombre": "Bulbasaur",  "tipo": "Planta"},
    {"id": 2, "nombre": "Charmander", "tipo": "Fuego"},
    {"id": 3, "nombre": "Squirtle",   "tipo": "Agua"},
]
```

## Create: añadir con un id único

Al crear un registro necesitas un id **nuevo**. La regla segura es *el id más alto que ya existe, más
uno*. Así nunca repites un id, aunque hayas borrado alguno:

```python
nuevo_id = max((p["id"] for p in pokedex), default=0) + 1
pokedex.append({"id": nuevo_id, "nombre": "Pikachu", "tipo": "Eléctrico"})
```

<Pitfall>
No uses `len(pokedex) + 1` para el id. Si borras un registro del medio, la longitud baja y acabarás
**reutilizando** un id que ya estaba en uso. `max(...) + 1` siempre da un id libre. El `default=0`
cubre el caso de la Pokédex **vacía**.
</Pitfall>

{/* sol:
pokedex = [{"id": 1, "nombre": "Bulbasaur"}, {"id": 2, "nombre": "Charmander"}]
nuevo_id = max((p["id"] for p in pokedex), default=0) + 1
print(nuevo_id)
*/}

## Read: buscar y filtrar

una línea — por ejemplo, todos los Pokémon de tipo Planta:

## Update: actualizar por id

Buscas el registro por su id y cambias el campo. Como el diccionario es **mutable**, modificarlo dentro
del bucle cambia el que está en la lista:

```python

    if p["id"] == objetivo:
        p["hp"] = nuevo_hp
        break
```

## Delete: borrar por id

La forma más limpia de borrar es **reconstruir** la lista con todos menos el que sobra, otra vez con
una comprensión:

```python
pokedex = [p for p in pokedex if p["id"] != objetivo]
```

## Guardar y cargar: JSON

Para que la Pokédex **no se pierda** al cerrar el programa, la conviertes a texto con `json.dumps` y la
recuperas con `json.loads`. En el proyecto lo escribirás a un archivo (`json.dump` / `json.load`,
Módulo 3); la idea es la misma:

```python
import json
texto = json.dumps(pokedex)     # lista -> texto
copia = json.loads(texto)       # texto -> lista
```

## Separa la lógica del menú

El truco de un código limpio: cada operación CRUD es **una función** que recibe la lista y trabaja con
ella (`crear`, `buscar`, `actualizar`, `borrar`). El menú solo **llama** a esas funciones. Así puedes
probar la lógica sin el menú, y cambiar el menú sin tocar la lógica.

## Mini-ejercicios

<Collapsible title="1. ¿Por qué max(...) + 1 y no len(...) + 1 para el id?">

Porque `len` cuenta cuántos hay ahora. Si borras uno del medio, la longitud baja y `len + 1` te da un
id que **ya existe**. `max(...) + 1` mira el id más alto usado, así que siempre da uno libre.

</Collapsible>

<Collapsible title="2. ¿Qué hace default=0 en max(...)?">

Evita el error cuando la lista está **vacía**: `max` sin elementos falla, pero `max([], default=0)`
devuelve `0`, así que el primer id será `1`.

</Collapsible>
