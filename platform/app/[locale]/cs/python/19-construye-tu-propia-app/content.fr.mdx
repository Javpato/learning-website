# Construis ta propre app de données

<Accroche>« Derrière toute app et tout jeu vidéo, c'est la même chose : créer, lire, mettre à jour et supprimer des données. Apprends ce squelette et tu pourras tout construire. »</Accroche>

Un Pokédex, l'inventaire d'un jeu, un réseau social, une boutique : sous le capot, tous font la même
chose, les quatre opérations **CRUD** (*Create, Read, Update, Delete*). Ce chapitre t'enseigne ce
motif avec des données en mémoire, pour que dans le **Projet 9** tu construises ton propre **Pokédex**
à partir de zéro.

## Ce qu'est CRUD

```text
Create  → créer un enregistrement
Read    → lire / chercher des enregistrements
Update  → mettre à jour un enregistrement
Delete  → supprimer un enregistrement
```

## L'enregistrement : un dictionnaire avec un id

Chaque chose que tu ranges (un Pokémon, un objet, un utilisateur) est un **enregistrement** : un
dictionnaire avec ses champs et, très important, un **id** unique qui l'identifie.

```python
pikachu = {"id": 1, "nombre": "Pikachu", "tipo": "Électrik", "hp": 35}
print(pikachu["nombre"])   # Pikachu
```

## Tous les enregistrements : une liste

La base de données entière est une **liste** de ces dictionnaires. On l'appellera `pokedex` :

```python
pokedex = [
    {"id": 1, "nombre": "Bulbizarre", "tipo": "Plante"},
    {"id": 2, "nombre": "Salamèche",  "tipo": "Feu"},
    {"id": 3, "nombre": "Carapuce",   "tipo": "Eau"},
]
```

## Create : ajouter avec un id unique

Quand tu crées un enregistrement, il te faut un **nouvel** id. La règle sûre est *l'id le plus élevé
qui existe déjà, plus un*. Ainsi tu ne répètes jamais un id, même si tu en as supprimé :

```python
nuevo_id = max((p["id"] for p in pokedex), default=0) + 1
pokedex.append({"id": nuevo_id, "nombre": "Pikachu", "tipo": "Électrik"})
```

<Pitfall>
N'utilise pas `len(pokedex) + 1` pour l'id. Si tu supprimes un enregistrement du milieu, la longueur
baisse et tu finiras par **réutiliser** un id déjà en usage. `max(...) + 1` donne toujours un id libre.
Le `default=0` couvre le cas du Pokédex **vide**.
</Pitfall>

## Update : mettre à jour par id

le modifier dans la boucle change celui qui est dans la liste :

## Delete : supprimer par id

La façon la plus propre de supprimer est de **reconstruire** la liste avec tous sauf l'intrus, encore
avec une compréhension :

```python
pokedex = [p for p in pokedex if p["id"] != objetivo]
```

## Sauvegarder et charger : JSON

Pour que le Pokédex ne soit **pas perdu** à la fermeture du programme, tu le transformes en texte avec
`json.dumps` et tu le récupères avec `json.loads`. Dans le projet tu l'écriras dans un fichier
(`json.dump` / `json.load`, Module 3) ; l'idée est la même :

texto = json.dumps(pokedex)     # liste -> texte
copia = json.loads(texto)       # texte -> liste

## Sépare la logique du menu

L'astuce d'un code propre : chaque opération CRUD est **une fonction** qui reçoit la liste et travaille
dessus (`crear`, `buscar`, `actualizar`, `borrar`). Le menu ne fait qu'**appeler** ces fonctions. Ainsi
tu peux tester la logique sans le menu, et changer le menu sans toucher à la logique.

## Mini-exercices

<Collapsible title="1. Pourquoi max(...) + 1 et pas len(...) + 1 pour l'id ?">

Parce que `len` compte combien il y en a maintenant. Si tu supprimes un enregistrement du milieu, la
longueur baisse et `len + 1` te donne un id qui **existe déjà**. `max(...) + 1` regarde l'id le plus
élevé utilisé, donc il donne toujours un id libre.

</Collapsible>

<Collapsible title="2. Que fait default=0 dans max(...) ?">

Il évite l'erreur quand la liste est **vide** : `max` sans éléments échoue, mais `max([], default=0)`
renvoie `0`, donc le premier id sera `1`.

</Collapsible>
