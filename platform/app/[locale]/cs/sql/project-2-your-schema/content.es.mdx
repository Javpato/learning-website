# Proyecto 2 · Construir un esquema — la funcionalidad de lista de deseos

<Accroche>« Una funcionalidad real nace de la misma manera: diseñas una tabla, la rellenas, la editas, la limpias. »</Accroche>

## Intuición

Estás añadiendo una **lista de deseos** (wishlist) a la tienda: los clientes guardan productos que quieren comprar más tarde.
Este proyecto encadena todo lo de los capítulos 1 y 2 — `CREATE`, `INSERT`, `UPDATE`,
`DELETE` y `SELECT` — en una construcción breve. Cada paso es comprobable. Si un paso sale
mal, pulsa **Reset DB** y vuelve a empezar el paso afectado.

## La construcción

Una entrada de la lista de deseos enlaza un cliente con un producto, con la fecha en que se guardó:
`wishlist(wish_id, customer_id, product_id, added_on)`. Cada paso vuelve a crear la tabla en
la misma ejecución para que se corrija de forma aislada.

<Collapsible title="Una solución">

```sql
CREATE TABLE wishlist (
  wish_id INTEGER PRIMARY KEY AUTOINCREMENT,
  customer_id INTEGER,
  product_id INTEGER,
  added_on TEXT
);
INSERT INTO wishlist (customer_id, product_id, added_on) VALUES
  (3, 1, '2024-09-10'),
  (8, 4, '2024-09-12');
SELECT customer_id, product_id, added_on FROM wishlist ORDER BY added_on;
```

Cualquier `customer_id` válido (1–10) y `product_id` (1–13) funciona.

## Cierre

Diseñaste una tabla, la poblaste, editaste una fila y eliminaste otra — una porción completa de
funcionalidad en SQL. Hasta ahora cada consulta ha leído *todas* las filas coincidentes o filtrado con un solo
`WHERE`. El **capítulo 3 · Filtrado** profundiza en el `WHERE`: `AND`/`OR`, `IN`, `BETWEEN`,
`LIKE`, y el comportamiento delicado de `NULL`.
