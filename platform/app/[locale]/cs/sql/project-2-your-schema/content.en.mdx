# Project 2 · Build a schema — the wishlist feature

<Accroche>« A real feature is born the same way: design a table, fill it, edit it, clean it up. »</Accroche>

## Intuition

You're adding a **wishlist** to the shop: customers save products they want to buy later.
This project chains together everything from Chapters 1–2 — `CREATE`, `INSERT`, `UPDATE`,
`DELETE`, and `SELECT` — into one short build. Each step is checkable. If a step goes
wrong, press **Reset DB** and start the affected step again.

<SqlSchema />

## The build

A wishlist entry links a customer to a product, with the date it was saved:
`wishlist(wish_id, customer_id, product_id, added_on)`. Each step recreates the table in
the same run so it grades in isolation.

## Your turn (open-ended)

<SqlExercise
  task="Build the wishlist from scratch (create, then add at least two wishes of your own using real customer_id and product_id values from the seed). <Collapsible title="A solution">

```sql
CREATE TABLE wishlist (
  wish_id INTEGER PRIMARY KEY AUTOINCREMENT,
  customer_id INTEGER,
  product_id INTEGER,
  added_on TEXT
);
INSERT INTO wishlist (customer_id, product_id, added_on) VALUES
  (3, 1, '2024-09-10'),
  (8, 4, '2024-09-12');
SELECT customer_id, product_id, added_on FROM wishlist ORDER BY added_on;
```

Any valid `customer_id` (1–10) and `product_id` (1–13) works.
