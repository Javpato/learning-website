# Definir y modificar datos — DDL y DML

<Accroche>« Primero *das forma* a los datos (DDL), luego los *rellenas y editas* (DML). »</Accroche>

## Intuición

El capítulo 1 solo *leía* tablas. Ahora vas a construirlas y remodelarlas. SQL se divide aquí en
dos familias: el **DDL** (Lenguaje de Definición de Datos) define la estructura — `CREATE TABLE`,
`ALTER TABLE`, `DROP TABLE`; el **DML** (Lenguaje de Manipulación de Datos) modifica las filas de dentro —
`INSERT`, `UPDATE`, `DELETE`. Todo lo que sigue se ejecuta sobre la base de datos de ejemplo en tu
navegador. ¿Has roto algo? Pulsa **Reset DB** para volver a sembrarla.

> ideas son idénticas, las escrituras difieren ligeramente — lo señalamos sobre la marcha.

## Sintaxis

**CREATE TABLE** — nombra cada columna y su tipo. SQLite tiene tres tipos de almacenamiento básicos:
`INTEGER`, `REAL` (coma flotante), `TEXT`. (No hay un tipo `DATETIME` aparte; las fechas se
guardan como `TEXT` en formato ISO, igual que hace la siembra inicial.)

```sql
CREATE TABLE suppliers (
  supplier_id  INTEGER PRIMARY KEY AUTOINCREMENT,  -- SQL Server: IDENTITY(1,1)
  name         TEXT NOT NULL,
  country      TEXT,
  rating       REAL
);
```

**ALTER TABLE** — modifica una tabla existente. SQLite admite:

```sql
ALTER TABLE suppliers ADD COLUMN phone TEXT;       -- añadir una columna
ALTER TABLE suppliers RENAME COLUMN phone TO tel;  -- renombrarla
ALTER TABLE suppliers DROP COLUMN tel;             -- eliminarla
```

**DROP TABLE** — elimina la tabla entera y sus datos:

```sql
DROP TABLE suppliers;
DROP TABLE IF EXISTS suppliers;   -- sin error si no existe
```

**INSERT / UPDATE / DELETE** — los verbos a nivel de fila:

```sql
INSERT INTO categories (category_id, name) VALUES (5, 'Garden');
UPDATE products SET price = price * 1.10 WHERE category_id = 1;
DELETE FROM products WHERE stock = 0;
```

## Errores comunes

<Pitfall>

**Un `UPDATE` o un `DELETE` sin `WHERE` afecta a *todas* las filas.** `DELETE FROM products;`
vacía la tabla entera; `UPDATE products SET price = 0;` pone todos los precios a cero. Escribe siempre
primero el `WHERE`, pruébalo idealmente como un `SELECT`, *luego* cámbialo por `UPDATE`/`DELETE`.

</Pitfall>

<Pitfall>

**Dialecto: el auto-incremento y los tipos difieren.** SQL Server usa `IDENTITY(1,1)` y tipos
como `NVARCHAR`/`DATETIME`; SQLite usa `AUTOINCREMENT` y simplemente `INTEGER`/`REAL`/`TEXT`,
guardando las fechas como texto ISO. Usa también `LIMIT n` (no `TOP n`) y `||` para la
concatenación de cadenas (no `+`).

</Pitfall>

<Collapsible title="P: Insertar un cliente proporcionando solo first_name, last_name y signup_date — ¿está permitido?">

Sí, siempre que cada columna que *omitas* admita NULL o tenga un valor por defecto. `country` y
`email` admiten NULL, pero `signup_date` es `NOT NULL`, así que hay que proporcionarlo:

```sql
INSERT INTO customers (customer_id, first_name, last_name, signup_date)
VALUES (11, 'Ada', 'Lovelace', '2024-08-01');
```

</Collapsible>

```sql
UPDATE orders SET status = 'void' WHERE status = 'cancelled';
SELECT order_id, status FROM orders WHERE status = 'void';
```
