# Querying data — SELECT

<Accroche>« SQL is *declarative*: you describe **what** you want, not **how** to fetch it. »</Accroche>

## Intuition

A relational database is a set of **tables** — grids of rows and columns. Asking a
question of the database is called a **query**, and almost every query starts with the
same verb: `SELECT`. You name the columns you want, the table they live in, and
optionally how to filter, order and limit the rows. The database engine figures out the
*how*.

## Syntax

The anatomy of a basic query, in the order the clauses are written:

```sql
SELECT   column1, column2      -- which columns (use * for all)
FROM     table                 -- which table
WHERE    condition             -- keep only rows matching this
GROUP BY column                -- collapse rows into groups
HAVING   group_condition       -- keep only groups matching this
ORDER BY column [ASC | DESC]   -- sort the result
LIMIT    n;                    -- return at most n rows
```

A few essentials:

- `SELECT *` returns **every** column. `SELECT name, price` returns just those two.
- `DISTINCT` removes duplicate rows: `SELECT DISTINCT country FROM customers`.
- `ORDER BY price DESC` sorts from highest to lowest.
- `LIMIT 3` returns only the first three rows (handy with `ORDER BY` for "top N").
- You can rename a column in the output with `AS`: `SELECT price AS cost`.

## Worked example

"List the three most expensive products, showing only their name and price."

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 3;
```

The engine reads every row of `products`, keeps the `name` and `price` columns, sorts by
`price` from high to low, and hands back the first three. Run it and try changing `DESC`
to `ASC`, or `3` to `5`.

## Common pitfalls

<Pitfall>

**The clauses must appear in the right order.** `SELECT … FROM … WHERE … GROUP BY …
HAVING … ORDER BY … LIMIT`. Putting `ORDER BY` before `WHERE`, or `WHERE` after `GROUP
BY` (instead of `HAVING`), is a syntax error.

</Pitfall>

<Pitfall>

**`SELECT *` is convenient but rarely what you want in real code.** It ties your query to
the table's current column layout and ships data you don't need. Name the columns you
actually use.

</Pitfall>
