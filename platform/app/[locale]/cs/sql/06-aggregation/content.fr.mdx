# Agrégation

<Accroche>« Arrêtez de regarder les lignes une à une. L'**agrégation** condense plusieurs lignes en un seul nombre — un comptage, un total, une moyenne. »</Accroche>

## Intuition

Jusqu'ici, chaque requête renvoyait des *lignes*. L'agrégation renvoie des *résumés* : combien
de commandes, le chiffre d'affaires total, le prix moyen. Une **fonction d'agrégation** replie
toute une colonne en une seule valeur. Ajoutez `GROUP BY` et vous obtenez un résumé **par groupe** —
le chiffre d'affaires par catégorie, les commandes par client, et ainsi de suite.

<SqlSchema />

## Syntaxe

```sql
-- agrège sur toute la table → une seule ligne
SELECT COUNT(*), SUM(quantity), AVG(unit_price), MIN(price), MAX(price)
FROM order_items;

-- GROUP BY → une ligne par groupe
SELECT status, COUNT(*) AS n
FROM orders
GROUP BY status;

-- HAVING filtre les GROUPES (après agrégation) ; WHERE filtre les LIGNES (avant)
SELECT customer_id, COUNT(*) AS orders
FROM orders
WHERE status = 'shipped'      -- ne garder d'abord que les lignes expédiées…
GROUP BY customer_id
HAVING COUNT(*) >= 2;         -- …puis garder les groupes ayant 2 commandes expédiées ou plus
```

Les fonctions d'agrégation : `COUNT(*)` compte les lignes ; `COUNT(col)` compte les valeurs non
NULL de `col` ; `SUM`, `AVG`, `MIN`, `MAX` font ce qu'elles disent. Enveloppez les montants/moyennes
dans `ROUND(…, 2)` pour un affichage propre.

## Pièges classiques

<Pitfall>

**Ne sélectionnez pas une colonne non agrégée qui n'est pas dans `GROUP BY`.** Une requête comme
`SELECT name, COUNT(*) FROM products GROUP BY category_id` est mal définie — il y a plusieurs
`name` par catégorie, alors lequel afficher ? Groupez aussi par cette colonne, ou enveloppez-la
dans une agrégation. (SQLite ne lèvera pas d'erreur, mais il renvoie la valeur d'une ligne
arbitraire — une source classique de rapports erronés.)

</Pitfall>

<Pitfall>

**`WHERE` contre `HAVING`.** `WHERE` filtre les lignes individuelles *avant* le groupement ;
`HAVING` filtre les *groupes* après l'agrégation. « Seulement les commandes expédiées » est un
`WHERE status = 'shipped'`. « Seulement les clients ayant 2 commandes ou plus » est un
`HAVING COUNT(*) >= 2`. On utilise souvent les deux dans une même requête.

</Pitfall>

## Mini-exercices

<Collapsible title="Q : Pourquoi COUNT(email) pourrait-il être inférieur à COUNT(*) pour les clients ?">

`COUNT(*)` compte chaque ligne (10). `COUNT(email)` ne compte que les lignes où `email` n'est
**pas NULL** (8, puisque deux clients n'ont pas d'e-mail). Les agrégations ignorent les NULL.

</Collapsible>

<Collapsible title="Q : Comment compter le nombre de pays distincts d'où viennent les clients ?">

```sql
SELECT COUNT(DISTINCT country) FROM customers;
```

</Collapsible>

