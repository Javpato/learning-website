# Aggregation

<Accroche>« Stop looking at individual rows. **Aggregation** collapses many rows into one number — a count, a total, an average. »</Accroche>

## Intuition

So far every query returned *rows*. Aggregation returns *summaries*: how many orders, the
total revenue, the average price. An **aggregate function** folds a whole column into a
single value. Add `GROUP BY` and you get one summary **per group** — revenue per category,
orders per customer, and so on.

<SqlSchema />

## Syntax

```sql
-- aggregate over the whole table → one row
SELECT COUNT(*), SUM(quantity), AVG(unit_price), MIN(price), MAX(price)
FROM order_items;

-- GROUP BY → one row per group
SELECT status, COUNT(*) AS n
FROM orders
GROUP BY status;

-- HAVING filters GROUPS (after aggregation); WHERE filters ROWS (before)
SELECT customer_id, COUNT(*) AS orders
FROM orders
WHERE status = 'shipped'      -- keep only shipped rows first…
GROUP BY customer_id
HAVING COUNT(*) >= 2;         -- …then keep groups with 2+ shipped orders
```

The aggregate functions: `COUNT(*)` counts rows; `COUNT(col)` counts non-NULL values of
`col`; `SUM`, `AVG`, `MIN`, `MAX` do what they say. Wrap money/averages in `ROUND(…, 2)`
for clean output.

## Common pitfalls

<Pitfall>

**Don't select a non-aggregated column that isn't in `GROUP BY`.** A query like
`SELECT name, COUNT(*) FROM products GROUP BY category_id` is ill-defined — there are many
`name`s per category, so which one should it show? Either group by that column too, or wrap
it in an aggregate. (SQLite won't error, but it returns an arbitrary row's value — a classic
source of wrong reports.)

</Pitfall>

<Pitfall>

**`WHERE` vs `HAVING`.** `WHERE` filters individual rows *before* grouping; `HAVING` filters
*groups* after aggregation. "Only shipped orders" is a `WHERE status = 'shipped'`. "Only
customers with 2+ orders" is a `HAVING COUNT(*) >= 2`. You often use both in one query.

</Pitfall>

## Mini-exercises

<Collapsible title="Q: Why might COUNT(email) be less than COUNT(*) for customers?">

`COUNT(*)` counts every row (10). `COUNT(email)` counts only rows where `email` is **not
NULL** (8, since two customers have no email). Aggregates skip NULLs.

</Collapsible>

<Collapsible title="Q: How do you count the number of distinct countries customers come from?">

```sql
SELECT COUNT(DISTINCT country) FROM customers;
```

</Collapsible>
